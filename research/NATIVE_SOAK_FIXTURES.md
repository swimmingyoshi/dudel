# Reproducible native soak fixtures

2026-10-17. These are generated test documents, not user artwork. Freeze the
executable and BUILD.json source-input hashes before a run. Together with the
reported fixture options, those hashes identify the generator and edit sequence.
The reference generator is `src/native_session.rs`, with its base dense mask from
`src/mask_transform_benchmark.rs`. It does not load user preferences/projects.

## Fixed workload

- Canvas: 2048 x 2048. One dense base raster with RGBA `[17,83,201,129]`, alpha
  locked, and a dense unlinked mask generated by `((x/7 + y/11)*37) % 251`.
- Additional raster count: selected total layer count minus one. Alpha is 140.
  Above four layers, alternating entries include clipping and Multiply blending.
- Sparse: each extra raster contains a deterministic 600 x 300 patch positioned
  by its layer index. Standard acceptance uses 20 total raster layers.
- Pattern: eight-/sixteen-pixel color patterns over every supported dense row.
- Noise: per-layer xorshift32 initialized with `0x12345678 + extra_layer_index`;
  RGB comes from its little-endian bytes, alpha stays 140. This challenges
  compression rather than using only highly compressible flat fills.
- Sustained rounds include 240 generated brush samples, 16 mask edit/preview/
  cancellation/undo/redo cycles, history release, save/reopen and matched idle
  checkpoints. Exact checks are outside the ordinary UI prefix timing.

Set `DUDEL_SOAK_ROUNDS=30`, `DUDEL_SOAK_LAYERS=20|32`, and
`DUDEL_SOAK_DENSITY=sparse|pattern|noise`. `scripts/run_soak.py` freezes and checks
the executable, runs sequential processes and records completion without silently
restarting a failed run. A release study requires three completed standard runs,
the maximum supported dense/noisy cases and a separate continuous two-hour session.

The current stroke generator uses one controlled brush configuration. Dedicated
ink/pencil/textured-preset coverage and the physical mixed drawing session remain
required; three repetitions of this one configuration do not establish those.

## Maximum masked payload boundary

A 2048-square raster holds 16 MiB of RGBA. Thirty-two full rasters already consume
512 MiB, so adding a dense 4 MiB mask would exceed the existing masked-document
payload budget. That earlier 32-layer dense generator was invalid and must not be
used for acceptance. Twenty-layer and sparse fixture geometry is unchanged.

The corrected 32-layer pattern/noise fixture retains 31 full rasters, fills the
first 1,536 rows of the last raster, and leaves its remaining 512 rows empty.
Raster payload is 508 MiB plus the 4 MiB mask: exactly **512 MiB**, at the actual
supported boundary. It preserves the 32-layer count, canvas area, dense mask,
clipping and blending. No document limit was raised to admit the workload.

Each completed native report now includes `extra_layer_bounds`,
`initial_raster_and_layer_mask_payload_bytes` and
`masked_document_payload_limit_bytes`, in addition to options and layer count.
These expose the supported geometry instead of implying every maximum-area
layer plus mask can simultaneously be full.

The geometry regression passes. The separately invoked
`native_session::tests::maximum_masked_noise_fixture_is_valid_at_the_payload_boundary`
constructs the real 512 MiB noisy fixture, checks populated/empty boundary rows and
validates the actual document; it passed in 26.15 seconds. See
[source-linked evidence](../benchmarks/native-dense-boundary-check.json).
It is ignored during ordinary suites because it allocates the full payload.

This construction test is not a native runtime soak, process-peak measurement,
save/open benchmark, physical tablet test or release acceptance. Those remain
separate gates. Peak and completed-job budgets are specified in DELIVERY_PLAN.md;
cached/cold results must be distinguished, and app restart is not a cold OS cache.
