# Review of the local effects and adjustment work

Reviewed `origin/master..0c5e42f` on 2026-10-29, concentrating on `c76cafd`,
`99d776a`, `e6838b8`, `a52018d` and `da51809`. There are 14 local commits,
including the documentation handoff. Fixes below are uncommitted. No push,
visibility change, external corpus download, or file move/deletion was performed.

**Findings, ranked by severity.** Line numbers refer to the reviewed working tree.
“Source-confirmed” means the relevant control/data path was inspected, not that
the scenario was exercised in the native UI. The five fixed bugs were each
reproduced with a failing regression before changing production code.

1. **P1, open: effect memory is not bounded across the document.**
   `src/layer_effects.rs:475`, `:513`, `:555`; `src/snapshot_memory.rs:69`.
   The draw budget charges one byte per pixel, although each output layer holds
   four-byte RGBA pixels, and each owner's cache starts a new budget. Two dense
   4096-square raster layers with 32 overlays each can retain roughly 4 GiB of
   effect pixels in addition to source pixels and working arrays, despite the
   document's 2 GiB stored-pixel limit. `CACHED_LAYERS = 4` is per cache, not a
   document-wide byte limit. Disabling/removing every effect also leaves the
   existing cache retained. Snapshot/history memory accounting does not visit
   those retained cache allocations. Source-confirmed; no multi-GiB stress run.
   Follow-up: budget actual retained bytes globally, account for them, and evict
   obsolete drawings. This needs a cache-lifecycle change, not a local counter fix.

2. **P1, open: older builds silently discard effects and adjustments on resave.**
   `src/binary_project.rs:45`, `src/tile_project.rs:49`,
   `PROJECT_FORMAT_V4.md:21`. Saving an effect/adjustment project, opening it in
   a pre-feature build, and saving again removes the ignored fields permanently.
   Documenting the omission does not protect artwork. Source/documentation
   confirmed; an old executable was not run. Recommend a format/capability gate
   that old readers reject before shipping these features. No format redesign
   was made during this review.

3. **P1, fixed: the effects window could create an unsavable document.**
   `src/effects_panel.rs:65`, `:138`. Adding a 33rd effect (or a two-part bevel
   at 31 entries) bypassed the queued edit validator and directly changed the
   document. Subsequent save/document edits fail validation. The regression
   proved invalid metadata and now proves the edit is rejected without touching
   history or the modified flag. Preset buttons also respect remaining capacity.

4. **P2, fixed: damaged adjustments panic during deserialization.**
   `src/adjustment.rs:72`, `:85`. An empty gradient-map stop list reached
   `ramp(stops)[0]` before document validation. Empty, single-point and reversed
   curve lists have analogous preparation hazards. The normal load worker
   catches its panic as a generic failure; direct decode callers unwind.
   Deserialization now validates settings before building tables. Regression
   covers all four malformed cases and requires an ordinary error, not a panic.

5. **P2, fixed: flat PSD order detection ignored native effects.**
   `src/psd_import.rs:984`. A top-first file containing red pixels with a green
   overlay above green pixels with a blue overlay saves as green. Comparing raw
   layer pixels chose the opposite order and imported a blue result. Both order
   candidates now expand effects once before sampling. The regression checks
   both top-first and bottom-first candidates.

6. **P2, fixed: records marked dropped were still decoded.**
   `src/psd_import.rs:747`. An unsupported color-balance layer with an unsupported
   channel encoding could fail the entire editable conversion even though it was
   already marked “left out.” The synthetic PSD regression contains a valid
   second raster and verifies it survives. Skipped records now consume their
   declared channel byte ranges without decoding or rendering them; truncated
   outer sections still fail bounds checks.

7. **P2, fixed: saved thumbnails omitted native layer effects.**
   `src/file_preview.rs:64`, `src/indexed_thumbnail.rs:43`. Red pixels with an
   opaque blue overlay appeared blue on the canvas/export but red in ordinary
   project previews and experimental indexed thumbnails. Both paths now expand
   effects once before sampling. Two regressions failed red-versus-blue before
   the fix and now pass.

8. **P2, open: shared effect-cache refresh can evade canvas invalidation.**
   `src/layer_effects.rs:553`, `src/canvas.rs:1301`, `:1320`,
   `src/canvas_textures.rs:854`, `:1651`. A background composite, color pick, or
   preview can refresh the shared cache for changed pixels before the canvas
   consumes its small damage rectangle. `expand_tracked` then reports no new
   draw. If the effect topology/metadata is unchanged, the bounded upload path
   updates only brush damage and adopts new signatures for untouched tiles, even
   where a displaced shadow changed. A later gesture-end scan can therefore
   consider those stale tiles current. Source-confirmed conditional path; no
   native timing reproduction. Track the effect generation actually presented
   by the canvas, independently of who last populated the cache.

9. **P2, open: queued effects edits use an obsolete settings list.**
   `src/effects_panel.rs:64`, `:147`; `src/pending_layers.rs:222`.
   While rendering is busy, toggle effect A and then change effect B before
   publication. Each edit starts from `self.doc` rather than projected effects,
   so the second whole-list replacement can restore A's old state. Slider
   changes also enqueue ordinary edits on every change, contrary to the promised
   one-gesture undo behavior. Source-confirmed; not exercised with a native queue
   backlog. Follow-up: project pending effect settings and use a coalesced gesture.

10. **P2, open: bevel synchronization can alter a different bevel.**
    `src/effects_panel.rs:196`, `:217`. Add two bevel presets. Changing the first
    bevel's highlight updates both neighboring shadow entries, including the
    second bevel's shadow, while leaving that second bevel's highlight unchanged.
    Moving another effect between halves instead stops synchronization entirely.
    Source-confirmed; not a native UI reproduction. Pair identity is needed;
    adjacency alone cannot distinguish multiple independently editable bevels.

11. **P2, open release follow-up: preserve the psd-tools license notice.**
    `src/adjustment.rs:5`, `:442`; `scripts/Package.ps1:145`.
    Source credit is present, but no psd-tools copyright/permission notice is
    included in the repository's notice inputs. The code follows the upstream
    brightness/contrast constants and calculation structure. For an adaptation,
    an “MIT” credit alone does not meet the upstream requirement to preserve the
    copyright and permission notice. Include it in source and binary distributions
    and cover this non-Cargo source in packaging. Verified against the upstream
    [license](https://github.com/psd-tools/psd-tools/blob/main/LICENSE) and
    [adjustment implementation](https://github.com/psd-tools/psd-tools/blob/main/src/psd_tools/composite/adjustments.py);
    no packaged candidate was produced in this review.

## Follow-up (2026-10-29, Claude)

All six open findings were fixed and committed with the review's fixes, each
with a regression test:

- **1, effect memory:** retained effect drawings across every cache share one
  1 GiB budget (`RETAINED_LIMIT`), evicting the least recently used first
  (`try_lock` only, never waiting while holding the registry); a drawing larger
  than the budget is used once and not kept. Switching effects off forgets the
  drawing. The per-draw budget counts 4 bytes per pixel. The Performance window
  shows the retained total.
- **2, old builds:** projects with effects or adjustment layers save under
  `DUDL\x06\r\n`; older builds reject that header instead of dropping data.
  Loader, recovery and the Explorer preview header accept it.
- **8, stale tiles:** drawings carry a unique generation; the canvas remembers
  the generations it last showed and does a full (signature-checked) update
  whenever they change, whoever drew them.
- **9, queued edits:** while the render queue is busy the window holds the
  gesture's list and sends one edit when the pointer lifts; later edits build
  on the last sent list until the queue publishes it.
- **10, bevel pairing:** bevel halves share a stored `pair` number; files saved
  before pairing (pair 0) fall back to unpaired neighbors.
- **11, license:** `LICENSE-psd-tools` (copyright and permission notice) is in
  the repository root, copied into binary packages with the other `LICENSE*`
  files and listed for source packages; the adapted code points to it.
